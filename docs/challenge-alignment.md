# Challenge alignment matrix

**Official source:** "Field Shift: Adapting Farms with NASA Data", 2026 NASA Space Apps Challenge, https://www.spaceappschallenge.org/2026/challenges/adapting-farms-with-nasa-data/ (verified 2026-10-30; `docs/research/challenge-source.md`). The challenge text is phrased as options ("may", "may consider") and states no judging criteria. Its Resources tab was due on 13 Nov 2026 and had not been published when this was written.

This is an **internal traceability record**, not NASA certification or endorsement. "Met" means the stated acceptance check passed in this repository's own tests on the development project; it does not mean agronomic validation.

Last updated: Phase 10 (Water & Energy planner), 2026-11-05. Phase 7: final review.

**Kind:** *Core* = the challenge's stated objective. *Optional* = something the brief suggests or lists as a possibility. *Ours* = our product choice. **Status:** Met · Partial · Not implemented (scope decision stated) · Not applicable.

## Core objectives

| ID | Requirement | Kind | Implementation | Evidence | Status | Limits |
|---|---|---|---|---|---|---|
| C1 | NASA environmental evidence has a traceable role in a farmer decision. | Core | NASA POWER daily weather drives ET0, the water balance, exposure indicators and the replay of every run. MODIS NDVI and POWER indicators inform the evidence page. Each value carries source, product version, period, native resolution and retrieval time; snapshots pin retrievals by id and hash. | `data/verification/evidence-trace.json` (raw response → stored metric → snapshot pin), `data/verification/simulation-trace.json` (raw POWER day = stored series → run → identical re-run), `data/verification/global-cases.json` (POWER v2.10.1 in three climates), `nasa-power-daily.json`, `modis-mod13q1-ornl.json`; E2E `e2e6` steps 3–5. | Met | POWER is a ½° × ⅝° model cell; the UI says the value describes the whole area. MODIS is shown as evidence but not used by the engine. |
| C2 | Local soil, crop characteristics and farmer history inform feasibility. | Core | Dated crop history defines the existing practice and planting windows; SSURGO AWC (US) or the farmer's soil test sets root-zone capacity; FAO-56 crop parameters (Tables 11/12/22) and USDA PLANTS families are published, pinned reference data. | Engine tests (baseline from history, no-window rejection, potential-only without soil), `global-cases.json` (SSURGO 191 mm/m in Iowa; unknown soil reported in Bangladesh; farmer soil value in Australia). | Met | Outside the US soil capacity is unknown unless the farmer enters it. Some crops lack FAO-56 rows or stage lengths (jute, mustard, canola stages, chickpea stages) and get partial indicators. |
| C3 | Farmer priorities and constraints affect comparisons. | Core | Exclusions, market access, water allocation, turnaround, planting windows and the canola return interval are hard constraints. Six priority weights set the ranking; ablation shows which priorities change it; the run page previews other weights with the engine's own `scoreOptions()` and "Save these priorities and run again" feeds them back. | Engine tests ("changes the ranking when priorities change", exclusions, allocation); `scoreOptions` reproduces stored rankings (test); `e2e6` (preview, undo, save and re-run, out-of-date marking). | Met | Weights are farmer judgments, not outcome scores. |
| C4 | Existing rotation and alternatives are compared on common inputs. | Core (text: "may compare at least three strategies"); our target: existing + two | One pinned snapshot per run; every option uses the same years, soil value and indicator definitions; indicators missing for any option are dropped for all. Up to three crop-set-distinct feasible alternatives; fewer is explained; an unknown baseline is requested, never invented. | Engine tests; `global-cases.json` (3 alternatives in each case); `e2e6`; Compare tab states the common inputs. | Met | Alternatives are chosen among combinations of the farmer's candidate crops and windows; the search is bounded for long rotations (stated in the result). |
| C5 | Explain reasons, evidence, benefits, tradeoffs, gaps and local-review risks. | Core | Per option: rank and priority contributions, better/worse against the existing practice with units, planting dates and sources, evidence used, rejected options and constraints, sensitivity and stability, data gaps, questions for a local expert, glossary; deterministic plain-language summary; optional AI draft limited to the stored result and its sources. | `e2e6` (Why view, explanation, AI unavailable and failure states); grounding tests (`src/domain/explain/grounding.test.ts`). | Met | Engine notes (gaps, assumptions, rejection details) are English in the Bangla interface. No real AI draft was produced in this environment (no key). |
| C6 | The tool supports farmer and agronomist judgment. | Core | Every result says it is a replay of past weather, not a forecast; scores are relative, not probabilities; no yield, profit or soil outcome; questions for local review; plans are the farmer's explicit choice; AI text is labelled a draft. | Pages `/runs/[id]`, `/methodology`; footer; `e2e6`. Phase 8: the result opens with a plain summary (ranked first among these options, better/worse than the current rotation) and a "Check it locally" note; each field shows a guided step path so a farmer always knows the next input. | Met | No agronomist has reviewed the outputs (see `docs/release-readiness.md`). No farmer usability test has been run on the Phase 8 layout. |

## Our product choices and supporting requirements

| ID | Requirement | Kind | Evidence | Status | Limits / scope decision |
|---|---|---|---|---|---|
| C7 | Global location selection with honest regional coverage. | Ours (grounded in global datasets) | Place search, coordinates and device location, reached by a flight over a satellite globe (Phase 9); per-source coverage and footprints; SSURGO "not available here" outside the US; three live cases on three continents incl. the Southern Hemisphere (`global-cases.json`). | Met | Calendars exist only for US states (NASS 2010) or the farmer's own dates; three cases are not validation elsewhere. Public OSM/Nominatim are development-scale services; the Esri satellite base may need an ArcGIS account for production. |
| D1 | Suggestions are not treated as mandates (three strategies, missions, AI, harmonisation). | Ours | `docs/astrapon-product-contract.md`. | Met (decision recorded) | — |
| D2 | Interactive 3D simulator with accessible equivalents. | Ours (3D is not required) | Real field geometry; day-by-day replay of stored engine state; side-by-side options; timeline; selected-date and monthly tables; WebGL fallback, quality presets, context-loss restart, reduced motion. FPS measured in `docs/release-readiness.md`. | Met | Terrain flat and plants illustrative (labelled). Software rendering is slow (≈ 10–14 FPS). |
| D4 | Saved work is private and reproducible. | Ours (contract) | RLS on 25 tables; `test:db` 17/17; immutable snapshots and results; identical re-run hashes (`simulation-trace.json`, `global-cases.json`); saved plans pinned to the result hash; new-session reopen and second-user 404 (`e2e6`). | Met | Not-found pages for another user's records return HTTP 200 with no data (streamed page). |
| D5 | Map, imagery and geocoding terms respected. | Ours | Visible attribution; submit-only Nominatim with a shared 1 req/s queue and cache; no tile prefetch. | Met (development scale) | Production traffic needs a commercial or self-hosted provider. |
| D6 | Evidence operations are bounded and honest. | Ours | Host allowlist, limits, timeouts, retries; persisted jobs; separate worker (local or GitHub Actions); stale and failed states; provider error pages redacted from messages (test). | Met | MODIS greenness is optional (own button, claimed last, not used by the engine); a first retrieval takes ≈ 2–3 min (last 10 years, 4 requests in flight). GitHub schedules can be delayed. |
| D8 | Water-supply and pumping-energy trade-offs for each compared rotation (Water & Energy planner). | Ours (product extension; not a NASA requirement or endorsement) | `docs/water-energy-methodology.md`, `docs/water-energy-providers.md`; `water.test.ts` (35 tests incl. the synthetic pump/PV reference); `data/verification/water-power-solar.json`, `water-overpass.json`, `water-groundwater.json` (USGS + Hub'Eau national adapters, GGMN global route, AU/BD/ZA/KE cases, outage); `test:db` 18/18; E2E 20/20 with and without WebGL. NASA POWER solar has a traceable role (C1); engine demand reused on common inputs (C4); gaps and unknowns first-class (C5). | Met | Groundwater observations exist only where networks share them (none found near Mymensingh or Nairobi); BWDB and BoM direct are not machine-accessible; public Overpass is development-scale; no pump curve, suction or hourly operation; English only. |
| D7 | Bilingual interface (English/Bangla). | Ours | Navigation, workspace, run journey, dates and digits. | Partial | Record forms, evidence texts and methodology are English (stated in Settings). |

## Optional considerations from the brief

| ID | Brief item | Kind | Status | Evidence or scope decision |
|---|---|---|---|---|
| C8a | Heat and frost exposure | Optional | Met | Frost and hot days during crops per option (reported, not scored: no sourced crop thresholds) and on the evidence page. |
| C8b | Water stress | Optional | Met (where soil is known) | Relative water supply, irrigation need, Ks and stress days in the replay; potential demand only without soil capacity. |
| C8c | Diversification | Optional | Met | Distinct crops and families, family repetition, legumes, deep-rooted plantings. |
| C8d | Periods when fields are typically bare | Optional | Partial | Scheduled bare-field days and the longest bare window come from the rotation schedule. **Not implemented:** observed bare-soil detection from imagery (needs field-scale HLS; MODIS 250 m mixes fields). |
| C8e | Cover-crop opportunities | Optional | Not implemented | **Scope decision:** the longest bare window is reported as context, but no cover-crop recommendation is made — there are no sourced cover-crop establishment and termination rules in the catalogue, and inventing them would break the contract. |
| D3a | SMAP soil moisture | Optional | Not implemented | **Scope decision:** different quantity and depth from the POWER root-zone wetness already shown; would need an AppEEARS job. Surface moisture anomaly is explained in the glossary only. |
| D3b | GPM IMERG precipitation | Optional | Not implemented | **Scope decision:** would double-count precipitation with POWER; one precipitation product is used consistently. |
| D3c | ECOSTRESS, Landsat/HLS as evidence | Optional | Not implemented | **Scope decision:** HLS is used only as a drawing aid; field-scale ET/imagery evidence deferred. |
| D3d | GRACE / GRACE-FO | Optional | Not applicable | Hundreds of km resolution; cannot inform a field decision (registry records the reason). |
| D3e | SRTM / NASADEM elevation | Optional | Not implemented | **Scope decision:** credentials work, but no sourced field-scale indicator (frost pockets, wet hollows) has been defined. |
| D3f | GEDI | Optional | Not implemented | Not evaluated; forest canopy structure is outside a cropland rotation decision. |
| D3g | AI / machine-learning techniques | Optional | Partial | Optional AI explanation drafting only, grounded and validated. No ML model ranks options (the deterministic engine is the method). |
| D3h | Resolution harmonisation | Optional | Met (by labelling) | Each source keeps its native resolution with footprints; no downscaling or fusion is done, and within-field differences are shown only when pixels resolve them. |
| D8 | Example access without an account | Ours | Partial | The public sample (`/sample`) shows the workspace with invented data, clearly labelled; **scope decision:** no seeded example run with real evidence was added — the own-field workflow is the acceptance path. |
